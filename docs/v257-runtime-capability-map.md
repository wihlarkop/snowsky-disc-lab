## Privilege boundary

The matrix's capability mappings are operation-specific inferences for the upstream rootful flow, not minimum requirements for every software probe. No user-namespace workaround was evaluated. A shorter capability list does not approve the stock launcher: its shared device, mount, registration and lifecycle effects require design review. Linux describes chroot as path resolution, not a sandbox ([chroot(2)](https://man7.org/linux/man-pages/man2/chroot.2.html)). Docker's privileged mode expands capabilities and host-device access ([Docker runtime privileges](https://docs.docker.com/engine/containers/run/#runtime-privilege-and-linux-capabilities)).
